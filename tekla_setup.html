Every new Tekla version and service pack meant working through the office's install guide by hand: the installers in order, then a dozen files copied from the server into folders that differ per version. Tekla Setup puts each step of the guide on a card, with its source on the server and a Browse button. Pick the version, tick the steps, press one button.

A

What it does

  1. 01

    Pick the version

    The list holds every version from 2023 on that has an installer folder on the server or is installed on the PC, newest first. Picking one fills every card's source from that version's folder.

  2. 02

    Check the sources

    Each source starts with .\, meaning the server folder. When a file on the server is replaced, Browse to the new one. A file picked inside the server folder is written with .\, anything else keeps its full path.

  3. 03

    Run the ticked steps

    The steps run in order, each card showing Running, OK or Failed. A failed step does not stop the others. Logs opens the full log, with a button to copy it.

The first time a file is overwritten, the original is kept beside it as .bak. Later runs leave that .bak alone, so it stays the file Tekla installed.

C

Patching, not copying

The guide copies a ready-made contentattributes_global.lst from the server. The server only has it up to TS2023, and Tekla ships a new one with every version, so copying an old file over a new one would lose the new version's attributes. The tool changes the one line instead, in the file the version installed.

The file is read and written as Latin-1, which maps every byte to one character, so everything but that line is written back byte for byte. Tested on the TS2026 file: the line went from dd.mm.yyyy to yyyy-mm-dd, and a second run found nothing to change.

D

The traps

Each of these broke the tool without saying why.

  • An admin session does not see mapped drives. The first version read everything from P:. Run as administrator, every server step failed with "Source not found", because Windows keeps mapped drives per logon session. The server folder is now the network path itself, \\10.168.1.3\Public\....
  • cmd mangles a quoted argument when elevated. A batch file that restarted itself as administrator closed straight after the admin prompt. It is now an exe whose manifest asks for admin rights before anything runs.
  • A hidden console swallows the error. With no window, a failed start looked like nothing happened. Anything that stops the script now shows in a message box.
  • A WPF window can only own another once it is shown. The logs window is given its owner when Logs is first pressed, not at start.
One file

Tekla-Setup.exe is a small C# launcher, compiled with the compiler that comes with Windows, with the PowerShell script stored inside it. It writes the script to the temp folder, runs it with no console and deletes it. Nothing to install, and Build-Exe.ps1 rebuilds it after a change.

F

Limitations

  • Another admin account gets the user files open

    If IT approves the admin prompt with their own account, user.ini, ribbons, property templates and shortcuts go to that account's AppData, not the user's.

  • The exe is not signed workflow

    Windows may show "Windows protected your PC" or "Unknown publisher", and some antivirus programs flag a new unsigned exe.

  • Old UI files known

    The newest ribbons on the server are for 2023 and the newest property panel is in the 2022 folder. Whether 2026 takes a Format="2023.0" shortcuts file is not checked yet.

  • Tekla must have been started once known

    UserSettings appears only on the first start, so the steps that need it fail until then.

  • The window waits for the installers workflow

    Each installer's wizard is clicked through, and the window does not respond until it closes.

  • Part mark elevation format is not a step known

    The guide only links to it, so it is still done by hand.

H

Running it

  1. Double-click Tekla-Setup.exe and accept the admin prompt.
  2. Pick the version. Untick the installers if the version is already installed.
  3. For a brand-new version, start Tekla once and close it before running the user.ini, ribbons, property templates and shortcuts steps.
  4. Press Run selected steps. A Failed card says why in Logs.
  5. Check in Tekla: Ctrl+E, File locations, XS_FIRM points at the server.
