01 - the problem

Identical by eye is not identical

The office marks assemblies and cast units in the EK_MARK UDA, as the numbering prefix plus a three-digit number. Identical pieces must share a mark, and every different piece must get the next one.

How a mark is built
PartExampleWhere it comes from
PrefixTT-The assembly or cast unit numbering prefix.
Start number001, 100, 200The numbering start number, set per floor. Each start number opens a range that ends where the next one begins.
DigitsTT-001Set in the window, 3 by default. Existing marks are kept as written.

Doing it by eye means opening pieces two at a time and comparing them part by part. A sandwich panel has two concrete layers, insulation, connectors, lifting anchors, embeds and rebar in every layer. A 10 mm shift of one anchor makes a different piece, and nothing in the model view shows it.

02 - running it

Scan, look, number

  1. Scan

    Lists the assemblies grouped by the prefix and start number set on the assembly or cast unit, with how many already carry a value. With a selection it scans only the selected assemblies, without one the whole model.

  2. Look before numbering

    Selecting rows on the Groups page selects all their assemblies in the model, so a group can be checked first. Clear the model selection before scanning the whole model again.

  3. Number

    Works through the selected rows only. Pieces are numbered in order of their centre of gravity along the axes set in Order. Existing values are kept, whatever they look like: each is checked against the first piece with that value, identical new pieces take it, and the rest get the next free number from the start number up.

  4. Read the results

    One row per piece, with its old value, new value and what happened. Selecting rows selects those assemblies in the model, and sorting by the new mark puts each set together.

The controls under the tabs
ControlDefaultWhat it does
Scan-Lists the groups, from the selection or the whole model.
Number-Compares the selected rows and writes the marks.
Clear-Empties the UDA of every piece in the selected rows, after a confirmation.
OverwriteoffClears the rows' values and numbers them afresh from the start number, after a confirmation, so identical pieces with two marks end up with one. Never remembered, so a new session never starts by clearing marks.
UniqueoffCompares nothing and gives every piece its own number, even an identical one.
OrderXYZThe axes pieces are numbered along: XYZ, YXZ, ZXY or ZYX. XYZ runs along X, then Y, then Z.
Digits3Digits in a new number, 1 to 9. 3 gives TT-001.
Tol1 mmHow far two pieces' geometry may differ and still count as the same.
WeldsonCompares welds by type, size and geometry.
RebaronCompares rebar, meshes and strands as Tekla numbers them. Number the model first.

Everything but Overwrite is remembered between sessions, in %APPDATA%\EK Mark\settings.txt. The UDA is always EK_MARK. A status line under the controls says what to do next.

03 - the comparison

Every part, in the main part's frame

Every part of the assembly is compared, not only the main part: the main part, every secondary, and every sub-assembly at any depth. The main parts must match each other. A piece with another main part is another piece, even when its parts are the same.

What is compared for each part
ComparedNot compared
Name, profile, material and finishClass, which is often only a colour
The solid's vertices, which carry the length, cuts, fittings and chamfers-
Bolt group holes: diameter, special hole type, slots and every positionThe bolt standard. Bolts are not part of the assembly.
Welds: type, size and the weld's own geometryWelds with no type and no size, which only tie a part into the assembly
Surface treatments: name, material, type and thickness-
Rebar, meshes and strands as Tekla numbers them: name, grade, class, position number, shape, diameter, count, and a bar's length and weightWhere the bars lie, so a cage turned with its piece, or with its hooks in another corner, still matches

Everything is read in the main part's local system and measured from the centre of the main part. Where the piece stands in the model drops out, and the relative position of every embed and hole stays in.

  • Turned copies match. A copy turned 90 or 180 degrees about any local axis still matches. That covers a beam modelled end to start and a square column turned a quarter.
  • Mirrored copies do not. Left and right hand pieces are different pieces.
  • Used numbers are skipped. A number already used anywhere in the model under the same prefix is never handed out again.
  • Ranges are guarded. A piece whose number would run into the next floor's range (TT-100 reaching TT-200) gets no mark and is shown in red.
04 - the live-model test

Two ways identical pieces split

The first version gave more marks than Tekla's own numbering. Each split traced back to something that looked different in the data but was the same piece.

Split one - weld frames

In BP- start 201 it gave 24 marks where Tekla has 20, and in 13 of the 15 split pairs the welds were the only difference. Welds were compared by their coordinate system, and identical welds can have that frame reversed or started at the other end.

The weld's polygons, mapped through its frame, describe where it actually is. Comparing those brought BP- start 201 to 20 marks.

Split two - a column turned 180 degrees

One column type stands in two rows of the building, one row turned 180 degrees to the other. The concrete, corbels and embeds matched once turned, but the stirrup hooks had been modelled facing the same way in both rows, and the welds that only tie the embeds in sat on opposite faces.

Rebar is now compared as Tekla numbers it, by its properties, and welds with no type and no size are skipped.

Choosing the tolerance
ToleranceResult on the live model
0.1 mmModelling noise splits identical pieces into extra marks.
1 mmAgrees with Tekla on 1,356 of 1,357 pairs, with no false match. The default.
5 mmThe first false match: two different pieces given one mark.

The one pair left over is two pieces that both get no mark, because their number would run into the next range. The same run showed that clash is real: SWP- start 101 has 442 pieces and would run past SWP-400, and SP- start numbers 100 and 101 sit one apart. That is why those pieces now get no mark instead of a number from the next range.

Every mark the macro has written on the BP- and SP- rows corresponds to exactly one Tekla assembly position.

05 - safeguards

Nothing half-written

  • Planned before written. All selected rows are planned before anything is written, so a failed comparison leaves the model untouched.
  • Undone on failure. A run that fails while writing undoes the marks it wrote.
  • Stale rebar numbering is caught. With Rebar on, a run warns before writing when Tekla's rebar numbering is out of date, and asks whether to write anyway.
  • A self-test on every open. 13 checks on the comparison and the mark format run each time the window opens: identical, turned 90 and 180 degrees, mirrored, inside and outside the tolerance, a different part, another main part, and parsing and formatting marks. If one fails, the window says not to trust the marks.
  • Controls lock while busy. Nothing can be started twice mid-run.
06 - limitations

What is left

What it compares, how it numbers and how it handles existing marks are settled. These are the known gaps.

  • Compared with the first piece of each mark only silent

    If that first piece is itself a conflict, new pieces are matched against the odd one out.

  • A weld with no geometry falls back to its frame geometry

    That is the less reliable comparison that split identical pieces before.

  • The tolerance is a box, not a sphere geometry

    It is checked per coordinate, and every point needs a partner but the pairing is not one-to-one. In rare cases two near-duplicate shapes could pass.

  • The window blocks while comparing interface

    By design, because the Open API is not thread-safe. 1,125 assemblies take about two minutes, about 30 seconds without rebar.

  • Clear has no undo of its own silent

    If it stops partway, the values it cleared stay cleared.

  • The current window has not been run inside Tekla not yet run

    Clear, the remembered options and the rebar warning compile, but have not been run in Tekla yet. The comparison and numbering were verified on the live model.

08 - build notes

How it is put together

  • One file. The whole macro travels as a single file in XS_MACRO_DIRECTORY\modeling. Tekla compiles it at startup.
  • The comparison is pure. The comparer uses no Tekla types, so the self-test runs without a model and the same code was driven from outside Tekla for the live-model test.
  • Written to a pre-C#6 subset, matching the other macros in the repository: no interpolation, no null-conditional, no null-coalescing.
  • Styled with HC Check, with the same flat palette and tab bar, so the macros read as one toolset.
