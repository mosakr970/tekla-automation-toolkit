Every model view is one row. Set the drawing name, the three titles and the saved drawing and view properties per row, tick the rows, and one button makes a GA drawing of each, with the view cut from the model view and centred on the sheet.

A

What it does

It is a modeling macro, run from the model with no drawing open, because the drawings are made from the model. Macros in the drawings folder are listed only inside the drawing editor.

  1. 01

    List the model views

    Every named model view, saved and open alike, is one row, sorted by name. A filter narrows the list, and the tick box in the header ticks every shown row, so hidden rows keep their ticks.

  2. 02

    Fill in the rows

    The drawing name, Title 1, 2 and 3, the drawing properties and the view properties. {view} in the name or a title is replaced by the model view's name. Rows are kept per model, so the next run starts where the last ended.

  3. 03

    Create drawings

    Every ticked and shown row is checked, then made into a GA drawing with one view. The Status column shows each new drawing's mark, or why the row failed. A drawing that could not be completed is deleted again, so a failed row leaves nothing behind.

Where the properties are read from

The lists are read from the files on disk each time the window opens and on Refresh: the model's attributes folder, the model folder, and each folder in XS_PROJECT, XS_FIRM and XS_SYSTEM with its attributes subfolder - the places Tekla's own dialogs read. A name found in several folders is listed once, and a firm folder that cannot be reached is skipped.

C

From model view to drawing view

Each drawing holds one view, built from the model view itself. Two of the model view's properties look like what is needed and are not.

  • DisplayCoordinateSystem is only the on-screen rotation. It is the angle the 3D view is looked at from. The plane the view lies in is ViewCoordinateSystem, used for both of the drawing view's coordinate systems.
  • WorkArea is in global coordinates. It is an axis-aligned box in the model, so its eight corners are moved into the view plane and boxed again. The box is then cut to the view depth up and down, since an axis view's work area often still spans the whole model.

A plan therefore shows its storey and an axis view its slice, at the scale and with the filters of the chosen view properties.

D

The traps

Each of these makes a drawing that is slightly wrong, without an error.

  • A missing properties file falls back to standard. Every row is checked against the lists first, and one naming a missing file fails with "not found".
  • The mark is empty after saving. The drawing gets its mark when it is saved, and is read again to show it.
  • PlaceViews leaves the view in the corner. Run inside Tekla it does not move the view at all. The view is moved to the middle of the sheet by its origin, after the view and the sheet are both read again.
The window

It stays above Tekla while pinned, and the pin beside the close button lets Tekla come in front. It runs a real message loop on its own STA thread, so the list scrolls smoothly, and the window is dragged by its top row.

F

Limitations

  • One view per drawing workflow

    A plan with a section beside it still needs the section added by hand.

  • A 3D model view comes out as a plan known

    It is drawn as a plan of its view plane, not as a 3D view.

  • The name rule knows two words known

    Only 'plaan' and 'teljel' set a starting name. Other views keep their own.

  • Duplicate names are allowed workflow

    Nothing stops two rows, or a second run, from making drawings of the same name.

H

Running it

  1. Install the macro: double-click DrawingCreator_1.0.tsep from config/release/, or open it in Tekla's Extension Manager. It installs into every Tekla version from 2023 on. Then restart Tekla.
  2. Close any open drawing. Start Drawing Creator from the model's Applications & components, under Macros.
  3. Filter the list if needed, tick the rows, and fill in the name, titles and properties.
  4. Press Create drawings. The Status column shows each drawing's mark, or why it failed.
